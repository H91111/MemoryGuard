# Memory Guard v0.2.0 使用说明

这是一个面向 Lifelong Learning Agent 的本地记忆治理产品。核心问题是：智能体不断接收新知识时，如何发现并控制旧任务退化、知识污染、过期误用和冲突强答。

## 1. 启动

解压到可写目录，安装 Python 3.11 或更高版本，然后双击根目录 `启动工作台.cmd`。无需安装 Python 依赖、无需账号、无需 GPU。启动窗口显示 ready 后会打开浏览器；使用期间保留窗口，关闭窗口或按 Ctrl+C 停止服务。

默认地址为 http://127.0.0.1:8765 。若端口被其他程序占用，在项目目录执行 `powershell -File start.ps1 -Port 8766`。

首次使用自动载入六步演示。正式使用可点“新建会话”，选“空白工作区”，再填写自己的项目名称。

## 2. 五分钟演示

1. **先验证已有能力。** 总览中选择 Atlas / v2，点击“运行登录任务”，看到 `/auth/token` 与 `access_token`，模拟器返回成功。
2. **观察学习的影响。** 点“负影响监测”，展开第5步：Atlas v2 从可调用变成澄清；Atlas v1 与 Beacon v2 保持原调用。第6步授权纠错后恢复。
3. **试写一条冲突知识。** 点“预检新知识”，填写 Atlas / v2，原文 `Atlas v2 登录路径为 /unverified/new。`，来源 `team-notes`。点击“① 预检学习影响”。看到两个任务保持、一个任务被阻断，此时正式记忆没有改变。
4. **决定是否学习。** 关闭对话框即可放弃；如要演示冲突处理，勾选风险确认，再点“② 确认保存事件”。重新运行 v2 任务，Agent 请求澄清，不会自行选择一个冲突值。
5. **恢复可用状态。** 将回放滑条移到第6步，点“从此处恢复”。系统创建新分支，原始完整历史仍可从会话列表切回。在新分支上运行任务，恢复成功。

产品中的风险确认是可选的业务操作步骤，不表示必须接受冲突。缺少日期、必要事实、复杂条件或来源权限时同样会保守澄清。

## 3. 日常操作

| 操作 | 使用方式 |
|---|---|
| 写入知识 | 先填写项目、版本、原文与来源，再预检。确认后才写入 |
| 日期范围 | 可填生效起点与终点，终点不包含；查询时填适用日期 |
| 定向纠错 | 选“授权定向纠错”、指定同范围目标、来源填本地已授权的 `maintainer`；原文只写一个待纠正属性 |
| 证据查看 | 记忆库点任意事实，查看原文、来源、跨度与决策 |
| 会话切换 | 上方会话下拉列表；重启后保留当前选择，空白会话不会被演示覆盖 |
| 导出备份 | 右上角“导出审计包”，保存当前完整会话 JSON；导出的是完整会话，不是滑条选中的前缀 |
| 导入恢复 | “导入审计包”选择 JSON，验证通过后进入新会话；失败不会替换当前会话 |
| 历史分支 | 回放到某步，再点“从此处恢复”；产生独立会话，可继续写入 |
| 自定义项目 | 任务栏可手动填项目与版本。没有独立模拟规格的项目只显示调用计划与证据，不伪称执行成功 |

工作区数据在 `runtime/`：SQLite 数据库和 `memory.workspace.json` 会话索引。完整搬迁可停止服务后复制整个 `runtime/`；跨目录重启时会话索引使用相对文件名。不要把正在使用的数据库文件单独改名。

## 4. 如何理解负影响指标

**工作台监测是行为比较，不是正确率评测。** 自动监测覆盖已有项目/版本的固定登录任务：

- 调用保持：学习前后均可调用，参数一致。
- 可用性下降：学习前可调用，学习后需澄清；这是影响信号，可能是阻止错误执行的正确防护。
- 参数变化：学习前后均可调用但参数不同；可能是必要适应，需要结合原文判断。
- 恢复调用：之前需澄清，学习后能生成调用。
- 仍需澄清：两边都无可调用结果，不计入“旧能力已保留”。

下降率分母为学习前可调用的任务数；分母为0时显示无基线。时间约束的知识在没有 as_of 的自动巡检中可能不可调用；可通过 Python `prepare(..., tasks=[...])` 显式指定适用时间和任务。监测逐步计数，同一任务可多次出现，不是独立样本数。网页逐步巡检上限200事件、自动范围上限100；更大的库用 Python `fork` 与 `compare` 选择两个检查点。

**时序评测使用独立本地模拟器。** 报告任务成功、旧任务保留、过期误用、冲突强答、多余澄清；原始 JSON 还记录跨范围引用和旧任务相邻成功→失败。所有数据仍是原项目的合成样例，不能当作独立研究或真实用户成绩。

## 5. 接入自己的 Agent

运行 `python -m examples.lifelong_agent` 查看“收到新知识→预检→按影响门控→检索执行”的最小示例。

`memory_guard.impact.prepare(memory, event, tasks=None)` 返回预检对象；把 `proposal.report` 交给用户查看，然后调用 `commit(memory, proposal, acknowledge=True)`。有风险时须明确确认；没有风险可直接 `commit(memory, proposal)`。预检后若底层记忆发生变化，提交会拒绝并要求重新预检。提取结果在预检时冻结，提交不重新调用不稳定的模型。

底层 `MemoryGuard.ingest` 和兼容的 `/api/ingest` 仍提供直接追加入口；它们不强制预检。需要强制学习门控的宿主应只暴露 prepare/commit。网页自定义写入默认走门控；六步演示直接重放已知事件。

## 6. 能力边界

此版交付为单机软件，范围是结构化开发 API 知识的外部记忆适应。核心离线使用规则提取与确定性规划器，没有训练模型权重，也不是通用自主 Agent。保留原有 BGE 检索与 Ollama 提取适配；本次不附模型权重、不声称完成新的生成模型实测。

来源 `maintainer` 是同一可信本机操作者配置的标签，不是多用户身份认证。服务仅监听127.0.0.1，不应暴露公网。哈希用于发现损坏，不是数字签名。复杂否定、单位换算、模糊版本范围、真实业务工具执行、多租户权限仍不在本版范围。
