## 2. 场景与研究问题

开发助手常常需要记住一个项目多个版本的 API。新文档并不总是替代旧文档：仍在维护的 v1 客户端继续使用 v1 路径，新客户端则需要 v2 的认证字段。重复消息、未经确认的笔记和后续纠错会同时进入记忆。

研究问题是：学习新知识后，助手能否提高新任务表现，同时保留答案仍然有效的旧任务？这里的持续学习采用固定权重下的非参数外部记忆适应，工程未实现模型参数训练。

四类连续场景

| 场景 | 观察重点 |
| --- | --- |
| 版本并存 | 学习 v2 后仍可完成合法 v1 任务；普通基线也获得项目、版本过滤。 |
| 正常知识学习 | v2 证据到达前应澄清，到达后能生成适用调用。 |
| 重复信息干扰 | 同一 v1 属性的重复观察会否挤出另一个必需属性。 |
| 冲突与授权纠错 | 证据矛盾时合理澄清，确认替代后恢复调用。 |

负影响的判定

仅当同一旧任务在前次检查点成功、前后均可回答、公开任务哈希及评分答案哈希均相同时，才把它纳入退化率分母。更新后失败计为退化。合法的 API 变更和真实冲突下的澄清，不被自动判为遗忘。分母为 0 时报告不适用。

目标使用者是本机操作的开发者。当天范围限定一个助手、一个固定模型、一类登录工具与上述四类记忆场景；多租户、模型训练和真实业务 API 执行不在本次交付范围。


## 3. 实现架构与信息边界

| 层次 | 实现与作用 |

| 检索与预算 | 按项目、版本及所需属性检索；治理上下文每个事实保留一份代表证据，审计库保留完整证据。 |

工作台仍使用确定性规划器；真实模型入口位于 Python SDK、CLI 和 day1 评测。此次接入没有把工作台预检改造成真实模型全能力预检。


## 4. 记忆更新、冲突与可恢复性

每条输入包含项目、版本、来源和原文。规则提取候选值并检查它能否在原文证据跨度中逐字找到；含条件、否定或缺失范围的输入保留待复核，避免把含糊文字直接转成明确事实。

| 机制 | 实现结果 |
| --- | --- |
| 版本隔离 | 不同项目、版本或不重叠有效区间的事实可并存，任务只读取适用范围。 |
| 重复关联 | 同一逻辑事实关联新增证据；检索保留代表证据与计数，审计不删原文。 |
| 冲突保留 | 同范围、同属性出现不同值时保留冲突；检测发生在上下文截断之前。 |
| 授权纠错 | 本机策略允许 maintainer 指定当前事实进行替代，保留 supersedes 关系和历史。 |
| 恢复与回放 | 从检查点创建独立历史分支；导出审计包、回放和状态摘要核验支持恢复。 |

副本预检的实际责任

prepare 固定一次提取结果，在独立副本试写，并在前后状态运行相同登录任务。报告呈现调用保持、阻断、参数变化、恢复及持续不可用；commit 核对原状态、预检指纹与风险确认后提交冻结候选。

这是一组行为信号，不等于有真值的正确率。默认自动探针只覆盖已知项目/版本的登录任务，仍由确定性规划器执行。直接 ingest 等入口仍存在；需要强制门控的宿主应收敛写入接口。


## 5. 真实 AI 的作用与运行记录

本次真实模型为 Qwen/Qwen3-0.6B-GGUF 的 Q8_0 GGUF 权重，revision 为 23749fefcc72300e3a2ad315e1317431b06b590a；推理服务采用 llama.cpp b11951 的 Windows CPU 构建。权重固定，没有微调。

共享适配器保留记忆可用性门控：已知缺证、冲突或不支持的范围将 schema 约束为 clarify，模型生成澄清文本；证据充分时，模型根据自然语言任务及记忆选择调用及路径、认证字段、工具参数和引用。适配层验证协议、范围和载荷，不用规则规划器修补参数，也不访问评分规格。错误路径由模拟器判失败。缺证/冲突时的澄清决策不归因于模型独立识别。

| --- | --- |
| 温度 / 随机种子 | 0 / 42 |
| 输出预算 / thinking | 384 tokens / 关闭 |
| 结构化响应 | JSON schema：status、tool_args、evidence_ids、reason |
| 请求与响应 | 216 次模型请求；216 条服务响应；7 次规划错误 |

## 6. 公平比较与评分协议

本次采用 6 条 acceptance 任务流，每条 4 个检查点、每检查点 3 个探针，三种方法共 216 次执行。开发集与验收集采用不同项目和任务 ID，但共享自编构造骨架；这些数据是开发者可见的合成样例，不是独立盲测。

| 方法 | 上下文策略 |
| --- | --- |
| 无跨任务记忆 | 每次只给当前任务，无历史证据；仍实际调用相同模型。 |
| 同范围最近优先 | 按相同项目、版本和所需属性过滤原样观察，再按最近优先截断。 |
| MemoryGuard | 相同输入事件，规则治理、重复合并、冲突前置检测、授权替代及字符检索。 |

三组使用相同提示词模板、生成参数和事实投影，上下文证据预算为 2048 字节、top-k=8。字节数按 canonical JSON facts 数组的 UTF-8 编码计量；task、system、schema 及 status/missing/conflicts 等治理元数据在证据预算外，各组完整提示词长度不一定相同。真实 tokenizer 用量另记。

| 指标 | 分母 |
| --- | --- |
| 可回答 / 新任务成功率 | 独立评分标签判可回答的任务 / 其中 category=new 的任务。 |
| 旧任务退化率 | 前次成功、前后可答，公开任务哈希与评分答案哈希均相同的相邻旧任务配对。 |
| 错误调用率 | 分别报告错误调用 / 全部执行，以及错误调用 / 实际调用。 |
| 多余澄清率 | 可回答任务中模型返回 clarify 的次数。 |
| 正确澄清率 | 不可回答任务中模型返回 clarify 的次数；error 不算澄清。 |

配置与输入/评分哈希在执行前保存。评分标签仅在模型返回后进入模拟器，任务输出不回写记忆。该实验比较整套记忆策略，没有单独的预检关闭消融，因此不单独归因预检收益。

## 8. 两个可核验案例

案例一：重复观察下仍有效的旧任务

任务：day1-acceptance-01-duplicates_and_conflict-anchor。项目 AcceptanceAPI1 / v1，检查点 13；评分答案哈希 a2ff881448ea6db9。

同范围最近优先：上下文 5 条事实、1774 字节；clarify：The required 'auth_field' is not present in the provided evidence. The 'login_path' is available, but the authentication。

MemoryGuard：上下文 2 条事实、727 字节；调用 /v1/acceptanceapi1/session，认证字段 key_1；模拟器 OK。

原样观察会为相同属性的每次出现支付上下文成本。治理方法合并逻辑事实，同时保留审计证据；本例只能支持这套记忆与上下文策略的整体比较。若两方法都失败，仍按失败报告。

案例二：保留治理方法的失败

任务：day1-acceptance-02-learn_v2-new；检查点 2，stage=learn_v2。

同范围最近优先：调用 /v2/acceptanceapi2/session，认证字段 token_2；模拟器 OK。

冲突后的合理澄清是所需行为；授权纠错要显式替代原事实，不能只把一条新笔记自动视为正确。报告保留模型本身的输出和错误，并将记忆策略效果与模型波动分开理解。

完整记录定位：结果目录 raw.jsonl，使用本页 task_id 与 method 搜索；评分文件 scoring-labels.jsonl 与输入 streams.jsonl 分开保存。

另对 3 个已保存失败案例按相同 temperature/seed 各复跑两次，共 6 次调用；状态及参数与原记录相同 6/6。复跑单独保存，不加入原实验分母，也不据此估计一般模型波动。
